# TodoHeap 开工细则

仓库结构、命令与表结构见仓库根 `AGENTS.md`；这里只放写代码与交付时要守住的结果。

## 代码与 UI

- 界面配色限定在 `neutral-*` 与 `accent-*` 两套色阶内，并复用 `.panel` / `.field` / `.btn-*` / `.chip` / `.eyebrow` 基元，让所有页面保持同一套观感。
- 图标统一走 `AppIcon`，维持全站线性图标风格；emoji 会跳出这套视觉语言。
- 圆角、阴影保持克制（`rounded-md` 为主，无大阴影与渐变），让内容而不是容器占据注意力。
- 中文注释说明这段代码负责什么，让维护者不必逐行反推意图、也不必翻历史找答案。
- 资源引用基于 `/TodoHeap/` 前缀，保证部署到子路径后仍能正确加载。

## 数据模型

- 完成状态只认 `completed_at` 是否为空，读写共用这一个事实来源，不引入第二套状态字段。
- 任务顺序只维护父级 `child_ids` 的数组顺序，新任务追加到末尾，让列表、任务图、Agent 读到的顺序始终一致。
- 所有顶层任务都归到根任务（`is_root`）下，新增走 `addTodo`（默认挂根），Agent 工具与导入同样如此，让列表、统计、回收站、Agent 共用同一棵树，根任务本身不暴露给用户。
- 删除保留 `deleted_at` 软删除，误删可恢复。

## 文档记录

- **关键词索引**：用户用现象描述界面时，能靠 `docs/zh/dev/keyword-index.md` 直接跳到代码位置。定位后把「用户说法 → 文件 + 锚点」补进最贴近的分组；同一对象的新说法并入同一条的「用户可能说」列，用 ` / ` 分隔，保持一份不重复的对照表。
- **需求记录**：`docs/zh/features/` 按功能域保留已实现需求的来龙去脉。新需求实现后在最贴近的篇目追加一行（日期 / 需求 / 实现要点与文件），没有合适篇目再新建并在 `index.md` 登记；英文文档暂不维护。
- **只记现状**：确保文档只体现项目最新现状，不含历史变更。行为改变时直接改写原条目，功能删减直接删掉对应描述。
- **缺陷记录**：修 bug 的结论留在 `docs/zh/dev/logic/` 的机制文档里，讲清受影响的机制、根因与修正后的现状逻辑，让后来者不必重走排查；没有篇目就新建并在该目录 `index.md` 登记，不写进 features。

## 验证

- 前端改动的交付标准是 `cd frontend && npm run build` 通过；改 store 再跑 `npm test`。
- 类型检查的已知噪声：`cd frontend && npm run type-check` 会因 vue-tsc 1.8 与 TS 5.9 不兼容直接崩，属已知问题，不作为新错误追。
- 文档改动的交付标准是 `cd docs && npm run build` 通过；`ignoreDeadLinks` 已关闭，死链会中断构建。
- 数据库处于实验阶段，结构随需求调整：迁移按领域拆成有序文件（表结构 / 索引 / RLS / 视图 / 函数 / 触发器 / Realtime），可直接改写既有迁移并重置，无需兼容历史数据。
- 迁移在没有本机 Postgres 时用 PGlite 按时间戳顺序执行 `supabase/migrations/*.sql` 验证；先建桩：`auth` schema、`auth.users(id uuid)` 表、`auth.uid()` 函数，以及 `anon` / `authenticated` 角色。

# dev-init

每次开始实现需求或修 bug，先走完这条流程再动代码。目标是让改动落在正确的文件、符合仓库现有约定，验证与记录都闭环。

## 1. 定位

读仓库根 `AGENTS.md` 的目录地图，确定改哪个文件；界面问题先查 `docs/zh/dev/keyword-index.md`，命中就直接打开对应位置。新功能先找现成承载点，找不到再新建。

完成判据：能说出要改的文件与锚点，并说明为什么不是相邻的其他承载点。

## 2. 核对约定

读仓库 `AGENTS.md` 指向的约定；TodoHeap 的细则在 `references/todoheap.md`，逐条核对本次涉及的项。

完成判据：列出的约束覆盖本次改动的每一类（代码 / 数据 / 文档），不只盯着最显眼的一条。

## 3. 实现

取最小完整集：能改现有代码就不新增实体，差异落在数据、配置或适配器上。每块代码上方一句目的性注释，写现状不写变更史。

完成判据：`git diff` 里的每个文件都是完成任务所必需。

## 4. 验证

按 `references/todoheap.md` 的「验证」执行；需要浏览器确认时先问用户，不自行启动调试。

完成判据：对应命令全部跑过且结果已报告，没有静默跳过的检查。

## 5. 记录

新需求写进 `docs/zh/features/` 最贴近的篇目；修 bug 更新 `docs/zh/dev/logic/`。只记现状。

完成判据：条目已落盘且索引已登记；缺陷没有写进 features。

## 6. 提交

改动到量就提交；仓库有发布脚本时走发布脚本。发现会话外改动先弹框问，选项含「直接提交」。

完成判据：工作区干净，或已说明哪些改动未提交及原因。

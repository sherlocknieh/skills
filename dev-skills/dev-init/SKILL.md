# dev-init

目标是让一个完全不了解项目的会话，只靠仓库内的 `AGENTS.md` 就知道先读什么、改完写哪里、怎么验证、能不能自己开浏览器。没有这份文件，每个会话都要重新摸索，重要结论也留不下来。

## 1. 摸清现状

- 没有 `AGENTS.md`：按第 3 步原样复制 `AGENTS-example.md`，占位符保留，交给后续会话弹窗自迭代。
- 有 `AGENTS.md`：逐节对照 `AGENTS-example.md`，缺哪节补哪节。
  - 缺 `开发流程` 或 `实现约定 → 调试约定`：优先补，这条决定 Agent 改完代码后会不会自行开浏览器。
  - 混入逐文件职责、命令清单、站点特性等细节：按第 3 步「细节外移」搬进 `docs/`，在模板对应位置留指针。
- 动手前列出要加、要改、要搬的条目，以及每条内容的新落点。

探测以下事实，只写确认过的：

- 技术栈、子项目与各自的包管理器（看 `package.json`、`pyproject.toml`、`go.mod` 与锁文件）
- 构建、测试、类型检查、lint 的真实命令（从 scripts 读取，不要臆造）
- 目录结构与已有文档
- 本来就失败的检查（先跑一次，避免把既有噪声误写成新问题）

## 2. 定记忆落点

按项目实际需要选路径，不套用固定技术栈。默认落点：

| 发生了什么 | 写到哪里 |
| --- | --- |
| 新功能或行为变化 | `docs/features/<域>.md` |
| 机制、根因 | `docs/logic/<机制>.md` |
| 用户对界面的说法 | `docs/keyword-index.md` |
| 架构取舍 | `docs/decisions/NNNN-<主题>.md` |
| 已知坑与噪声 | `docs/known-issues.md` |

仓库已有文档体系时沿用现有目录，不另建一套。

## 3. 写 AGENTS.md

以 `AGENTS-example.md` 为唯一模板，原样复制，不要凭记忆另写一份精简版。先解析模板的真实路径，不要照抄占位符路径：

```bash
# 项目内安装优先；dev-init 不装到全局，缺了就按 skills-init 的 dev 场景链接安装
DEV_INIT_DIR=$(dirname "$(readlink -f .agents/skills/dev-init/SKILL.md 2>/dev/null)")
test -f "$DEV_INIT_DIR/AGENTS-example.md"
cp "$DEV_INIT_DIR/AGENTS-example.md" AGENTS.md
```

复制后按以下纪律处理：

1. **复制时原样保留所有占位符**：`<项目名>`、`<一句话说明是什么>`、`[待定]` 等一个都不要改。它们是后续会话的待办清单和弹窗触发点。
2. **占位符由弹窗填**：后续会话遇到未填的占位符时，按「全局规则」里的 [询问]/[待定] 协议弹窗问用户，答案直接写回 `AGENTS.md`；用户当次不想答就原样保留。即使能从 `package.json`、构建脚本读到事实，也先向用户确认口径再写，不预填猜测内容。
3. **删除不适用的小节**（如没有前端就不留前端目录）可以，但**不得删除**：`开发流程`（含检验环节的 [询问]）、`实现约定 → 调试约定`、`记忆落点`、`自动提交`、`文档导航`。
4. 模板里的「调试约定」是硬规则：改完代码只用构建、测试、类型检查验证；启动浏览器、打开目标站点或操作已共享页面，必须先弹窗询问。项目有特殊验证方式时在它下面追加，不改写这条。

模板章节齐全即可，不以行数为门槛：流程与约定必须在 `AGENTS.md` 里，Agent 才会读；文件职责、命令清单、站点特性等细节放 `docs/`，并在模板的「文档导航」留指针。

### 细节外移（既有 AGENTS.md 塞了项目细节时）

用户说「按规范重写 AGENTS.md」「把项目特有内容拆到文档」，或第 1 步发现 `AGENTS.md` 混入细节时，按下面搬；只删不搬会让事实消失，搬完再去重。

| 原内容 | 新落点 |
| --- | --- |
| 逐文件职责、入口生命周期、站点或模块清单 | `docs/architecture.md` |
| 编码约定：handler 写法、清理函数、选择器契约、动态 DOM | `docs/conventions.md` |
| 站点改版、选择器失效、环境坑 | `docs/known-issues.md` |
| 开发环境、命令、版本号与发布机制 | 已有 `README-dev.md` 等文档就只留指针，不复制正文 |
| 新功能与机制来龙去脉 | 按第 2 步的记忆落点 |

拆分纪律：

- 每条事实只留一处：搬走的内容从 `AGENTS.md` 删除，不在两处各留一份。
- 文档导航的指针写「什么时候去读」（分支），不写「那个文件里有什么」。
- 事实原地可查：搬动前后逐条核对，站点清单、命令、约束这类内容不能因重写丢失。
- 搬完逐节对照模板：缺的章节补回来，尤其是 `调试约定`；不要为了变短而删掉流程与约定。
- 重写时同步更新 `.github/copilot-instructions.md` 链接，不复制正文（见第 4 步）。

## 4. 为 Copilot 建项目指令链接

Copilot 会读 `AGENTS.md`，但不保证最先加载，可能先读到代码；`.github/copilot-instructions.md` 保证最先注入。为它建一个指向项目 `AGENTS.md` 的符号链接，不复制正文：

```bash
mkdir -p .github
ln -sfn ../AGENTS.md .github/copilot-instructions.md
readlink .github/copilot-instructions.md   # 应为 ../AGENTS.md
```

- 用相对链接，仓库移动或重新 clone 后仍有效。
- 已有指向 `AGENTS.md` 的链接：跳过。
- 已有实体文件：内容与 `AGENTS.md` 相同就替换成链接；不同则先 `cp` 到 `.github/copilot-instructions.md.bak.<日期>` 再替换，并在报告里写出备份路径。
- 只处理 `.github/copilot-instructions.md`，不要动 `*.instructions.md` 等模块化指令。

## 5. 落盘

- 表格里的路径要真实可用：不预建空目录，首次记录时再建。
- 命令必须能原样复制执行，含必要的工作目录前缀。

## 6. 校验

- 逐节对照 `AGENTS-example.md`：`[询问]` 协议、项目基本认知、开发流程、定位流程、实现约定（含 `调试约定`）、记忆落点、`自动提交`、文档导航都在
- `调试约定` 明确写了「不要自行启动浏览器调试，必须先问用户」
- 每条验证命令都实际跑过一次，写清"本来是什么结果"
- 文档导航里的每个路径存在，或标注何时创建
- 占位符保留是正常状态：每个 `<...>` / `[待定]` 要么已按弹窗答案填写，要么原样留着等后续会话；不得填入未经确认的臆造内容
- 没有其他项目的示例残留（如 TodoHeap 路径、他人仓库名）；模板本身通用，复制后的文件里只应出现本项目已确认事实与自己的占位符
- 重写或拆分过时：原文件的事实逐条在新文件里有落点，站点清单、命令、约定三类重点抽查

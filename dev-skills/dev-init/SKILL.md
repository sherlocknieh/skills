# dev-init

目标是让一个完全不了解项目的会话，只靠仓库内的 `AGENTS.md` 就知道先读什么、改完写哪里、怎么验证。没有这份文件，每个会话都要重新摸索，重要结论也留不下来。

## 1. 摸清现状

- 有 `AGENTS.md`：只补缺失章节，不重写已有内容；动手前列出要加要改的条目。
- 没有：按第 3 步新建。

探测以下事实，只写确认过的：

- 技术栈、子项目与各自的包管理器（看 `package.json`、`pyproject.toml`、`go.mod` 与锁文件）
- 构建、测试、类型检查、lint 的真实命令（从 scripts 读取，不要臆造）
- 目录结构与已有文档
- 本来就失败的检查（先跑一次，避免把既有噪声误写成新问题）

## 2. 定记忆落点

按项目实际需要选路径，不套用固定技术栈。默认落点：

| 发生了什么 | 写到哪里 |
| --- | --- |
| 新功能或行为变化 | `docs/features/<域>.md` |
| 机制、根因 | `docs/logic/<机制>.md` |
| 用户对界面的说法 | `docs/keyword-index.md` |
| 架构取舍 | `docs/decisions/NNNN-<主题>.md` |
| 已知坑与噪声 | `docs/known-issues.md` |

仓库已有文档体系时沿用现有目录，不另建一套。

## 3. 写 AGENTS.md

模板控制在 40 行内，超出说明塞了不该放的内容：

```markdown
# <项目名>

<一句话：是什么、主要技术栈、子项目>

## 文档地图

| 要知道什么 | 去哪里 |
| --- | --- |
| 目录与文件职责 | ... |
| 用户说法 → 代码位置 | ... |
| 机制与约束 | ... |

## 开工流程

1. **定位**：按文档地图找承载文件；找不到就继续找，不改无关文件。
2. **核对约定**：只读与本次改动相关的条目。
3. **实现**：取最小完整集，能改现有代码就不新增实体。
4. **验证**：跑「验证」里的命令，结果如实报告，不跳过失败项。
5. **记录**：按「记忆落点」更新文档。
6. **提交**：改动到量就提交，工作区保持干净。

## 记忆落点（自动执行，不需要用户提醒）

| 发生了什么 | 写到哪里 | 判据 |
| --- | --- | --- |
| 新功能 | ... | 含日期、需求、实现要点与文件 |
| 机制或根因 | ... | 讲清现状逻辑 |
| 用户对界面的说法 | ... | 说法 → 文件:锚点 |
| 架构取舍 | ... | 背景、选项、结论、影响 |
| 已知坑 | ... | 现象、原因、规避方式 |

- 只记现状：行为变化直接改写原条目，不留变更史。
- 代码与文档在同一轮完成，不攒到以后。
- 删除功能就删对应文档，不写没有事实支撑的文档。
- 文档路径在「文档地图」登记，新增目录同步更新。

## 验证

| 改动范围 | 命令 |
| --- | --- |

## 维护

目录结构、命令或数据模型变化时同步更新本文件。
```

## 4. 落盘

- 表格里的路径要真实可用：不预建空目录，首次记录时再建。
- 命令必须能原样复制执行，含必要的工作目录前缀。

## 5. 校验

- 每条验证命令都实际跑过一次，写清"本来是什么结果"
- 文档地图里的每个路径存在，或标注何时创建
- 全文没有占位符和 TODO

## 6. 提交
